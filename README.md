## About

<img align="right" src="https://raw.githubusercontent.com/iamraaaey/iamraaaey/output/github-contribution-grid-snake-dark.svg" width="0" alt="" />

I build **production-grade software** where engineering rigor meets product intuition — systems that stay fast under load, codebases that stay readable at scale, and interfaces people actually enjoy using.

My work sits at the intersection of three disciplines:

- **Software Engineering** — distributed backends, event-driven architectures, clean domain modeling, and CI/CD pipelines built for teams that ship daily.
- **AI / Machine Learning** — deep learning, NLP, computer vision, and LLM/RAG systems taken from notebook prototypes to versioned, monitored, latency-budgeted inference services.
- **Full Stack & Product Engineering** — type-safe React/Next.js frontends over resilient APIs, designed with the accessibility, performance, and UX polish of a product team rather than a side project.

I care about the parts that survive the demo: observability, test coverage, cost per request, p99 latency, and the interface that makes complexity disappear. I write code that the next engineer can extend without a meeting.

## Featured Projects

<details>
<summary><b>&nbsp;Neural Intelligence Platform — Enterprise RAG & Document Reasoning</b></summary>

<br />

A multi-tenant retrieval-augmented generation platform that turns unstructured enterprise document archives into a governed, citation-backed question-answering layer with role-scoped access control.

| Attribute | Detail |
| :--- | :--- |
| **Stack** | Python · FastAPI · PyTorch · Transformers · PostgreSQL · pgvector · Redis · Next.js · Docker |
| **Scale** | 2M+ indexed document chunks across isolated tenant namespaces |
| **Performance** | p95 query latency under 400ms with hybrid retrieval and semantic response caching |
| **Security** | Row-level tenant isolation, JWT + refresh rotation, audit logging, PII redaction at ingest |
| **Impact** | Cut internal document research time by ~70% for pilot teams |
| **Repository** | [github.com/iamraaaey](https://github.com/iamraaaey?tab=repositories) |

Built around a hybrid retriever that fuses dense embeddings with BM25 lexical scoring, then reranks with a cross-encoder before generation. Every answer carries span-level citations back to source documents, and an offline evaluation harness scores faithfulness and retrieval recall on each release so regressions are caught before deployment rather than in production.

</details>

<details>
<summary><b>&nbsp;Distributed Commerce Engine — High-Throughput Transactional Backend</b></summary>

<br />

An event-driven commerce backend handling catalog, inventory, checkout, and fulfillment as independently deployable services communicating through an ordered event log.

| Attribute | Detail |
| :--- | :--- |
| **Stack** | Go · Node.js · PostgreSQL · Redis · Kafka · Kubernetes · Terraform · AWS |
| **Scale** | 10K+ requests/minute sustained, horizontally autoscaled across availability zones |
| **Performance** | p99 checkout latency under 220ms; 99.95% measured service availability |
| **Security** | OAuth2 + RBAC, idempotency keys, signed webhooks, encrypted secrets via KMS |
| **Impact** | Reduced infrastructure cost per order by ~35% after query and cache optimization |
| **Repository** | [github.com/iamraaaey](https://github.com/iamraaaey?tab=repositories) |

Inventory correctness is enforced through the saga pattern with compensating transactions, so a failed payment never leaves stock reserved. The outbox pattern guarantees exactly-once event publication, and every service exposes structured traces and RED metrics, making production incidents a matter of reading a dashboard rather than guessing.

</details>

<details>
<summary><b>&nbsp;Vision Analytics Suite — Real-Time Computer Vision Pipeline</b></summary>

<br />

A streaming computer vision system that ingests concurrent video feeds, runs detection and tracking on GPU, and surfaces live operational analytics through a reactive dashboard.

| Attribute | Detail |
| :--- | :--- |
| **Stack** | Python · PyTorch · OpenCV · ONNX Runtime · FastAPI · WebSockets · React · TimescaleDB |
| **Scale** | 30+ concurrent camera streams processed on a single GPU node |
| **Performance** | 60 FPS inference via ONNX quantization, dynamic batching, and frame-skip scheduling |
| **Security** | On-premise processing, anonymized identity vectors, configurable retention windows |
| **Impact** | Replaced manual monitoring workflows with automated real-time alerting |
| **Repository** | [github.com/iamraaaey](https://github.com/iamraaaey?tab=repositories) |

The inference path is decoupled from ingestion by a bounded frame queue with backpressure, so a slow consumer degrades frame rate instead of exhausting memory. Models are exported to ONNX and quantized to INT8, delivering roughly a 3x throughput gain over the baseline PyTorch graph with negligible accuracy loss.

</details>

<details>
<summary><b>&nbsp;Developer Experience Platform — Full Stack Product Suite</b></summary>

<br />

An end-to-end SaaS platform combining a type-safe API layer, a design-system-driven frontend, and a fully automated delivery pipeline built for a small team shipping continuously.

| Attribute | Detail |
| :--- | :--- |
| **Stack** | TypeScript · Next.js · tRPC · Prisma · PostgreSQL · Tailwind CSS · GitHub Actions · Vercel |
| **Scale** | 50+ typed API procedures across a shared monorepo with strict end-to-end type safety |
| **Performance** | Lighthouse 98+ across all pages; sub-second time to interactive on cold loads |
| **Security** | Session rotation, CSRF protection, zod-validated boundaries, granular permission checks |
| **Impact** | Reduced feature lead time from days to hours through preview deploys and automated checks |
| **Repository** | [github.com/iamraaaey](https://github.com/iamraaaey?tab=repositories) |

Types flow from the database schema through the API layer into React components without a single hand-written interface, which eliminates an entire category of runtime errors. Accessibility is enforced in CI alongside unit, integration, and end-to-end suites, so a merged pull request is a deployable pull request.

</details>
